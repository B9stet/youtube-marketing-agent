# 운명원 유튜브 댓글 마케팅 에이전트 기획안

**기준일:** 2026년 11월 26일

**제품 형태:** 운영자 컴퓨터에서 실행하는 유튜브 댓글 대시보드

## 1. 제품 개요

운영자가 연애 관련 유튜브 영상을 선택하면, 영상의 자막과 시청자 댓글을 바탕으로 장면과 고민을 정리하고 운명원 연애 사주에 대한 관심으로 이어지는 댓글을 만드는 도구다. 운영자는 장면과 시안을 확인하거나 수정한 뒤, 로그인한 전용 크롬 프로필에서 댓글을 게시하고 결과를 확인한다.

댓글은 영상 속 구체적인 대사나 상황에서 시작한다. 시청자의 반응은 공감, 응원, 조언, 비판, 답답함, 망설임, 장난 등 영상에 맞는 감정과 관점으로 작성한다. 운명원은 댓글의 끝부분에서 그 생각과 자연스럽게 연결하며, 그 뒤에 짧은 감상이나 혼잣말이 이어질 수 있다.

### 제작 의도

영상의 구체적인 장면과 이를 바라보는 시청자의 생각에서 출발해, 운명원 연애 사주에 대한 관심으로 이어지는 댓글을 만든다. 운영자는 댓글의 근거와 최종 문장을 직접 확인하고, 영상 탐색부터 게시 결과까지 한 화면에서 살펴볼 수 있다.

**핵심 설계와 선택 이유**

- **장면 선별:** 긴 자막을 약 60초 구간으로 나누고 시청자 반응, 영상 제목과 연애 관련 표현을 기준으로 관련 구간을 고른다. 선택한 장면과 주변 맥락을 활용해 댓글의 초점을 분명히 하고, 생성 요청에 들어가는 자막의 양을 줄인다.
- **참고 댓글 활용:** 인기 댓글에서 장면과 관련된 반응을 찾아 말투와 관점을 참고한다. 문장이나 개인사를 복사하지 않고, 같은 영상에서도 공감, 답답함, 조언처럼 서로 다른 시청자의 생각을 살린다.
- **Jev와 교정 규칙:** Jev의 항목별 진단 신호에 따라 프로그램이 정해진 규칙을 조합해 교정 지시문을 만든다. 같은 신호 조합에는 같은 지시문이 만들어지므로 무엇을 어떻게 고칠지 일관된 기준으로 관리할 수 있다.
- **시안 생성과 검토 분리:** 댓글이 생성되면 먼저 표시하고 Jev 검토는 별도로 진행한다. 운영자가 다음 시안의 설정을 고르는 동안 현재 글을 유지하며, 검토 결과를 각 시안과 원문에 연결해 늦게 도착한 결과가 수정한 글을 덮어쓰지 않게 한다.
- **게시 제한과 결과 확인:** 영상별 중복과 하루 상한을 저장된 이력으로 관리한다. 게시 여부가 불명확할 때도 중복 게시를 막고, 실제 게시 확인과 삭제 결과를 기록해 작업 상태를 살필 수 있게 한다.
- **뜨기 전 영상 탐색:** 조회수를 두 시점에 읽고 실제 증가량을 시간당으로 환산해 상승 중인 영상을 찾는다. 발견한 영상도 일반 영상과 같은 과정으로 댓글을 생성하고 게시할 수 있다.
- **AI 연결 분리:** 댓글 생성과 Jev 진단의 연결을 독립적으로 선택한다. 생성 모델을 바꾸더라도 동일한 진단과 교정 흐름을 이용할 수 있게 역할을 나눈다.
- **모델 선택:** 한국어 화자의 표현에 가장 가깝게 문장을 다듬을 수 있다고 판단해 Gemini 4 계열을 선택했다. 기본 생성 모델인 Hydrogen은 2026년 11월 26일 Google의 표준 유료 API 요금 기준으로 Gemini 4 계열 중 입력과 출력 토큰 단가가 가장 낮아, 반복적인 초안 생성과 교정의 비용도 함께 고려한 선택이다. [Google Gemini API 요금](https://aistudio.google.com/docs/pricing)

| 대상 영상 | 연애 주제의 유튜브 영상 또는 운영자가 직접 입력한 유튜브 영상 |

## 2. 화면 구성과 사용 흐름

대시보드는 영상 탐색, 댓글 초안 편집, 게시 확인의 세 영역으로 구성한다.

| 영역 | 주요 기능 |
| --- | --- |
| 영상 탐색 | 연애 영상 불러오기, 영상 링크 직접 입력, 뜨기 전 영상 찾기, 영상 선택 |
| 댓글 초안 편집 | 고민 한 줄과 댓글 초안 표시, 장면과 시청자 반응 확인, 다음 시안 설정, 진단 및 교정, 저장된 시안 비교 |
| 게시 확인 | 계정 선택, 댓글 미리보기, 게시 단계 표시, 당일 게시 수와 실행 기록 확인 |

상단의 연결 설정에서 댓글 생성 API와 Jev 진단 연결을 각각 고른다. 작업 이력 화면에는 시간, 영상, 사용 프로필, 댓글, 결과와 캡처가 표시된다.

### 기본 흐름

1. `영상 불러오기`를 눌러 연애 영상 목록을 보거나 유튜브 링크를 직접 입력한다.
2. 영상을 선택하면 자막과 시청자 반응을 수집하고, 추천 장면을 바탕으로 고민 한 줄과 첫 댓글 초안을 만든다.
3. 초안이 준비되면 먼저 화면에 표시하고, Jev 진단과 필요한 교정을 이어서 진행한다.
4. 운영자는 영상 장면, 참고 댓글의 관점, 말투와 댓글 내용을 확인한다. 다른 장면이나 관점으로 작성할 때는 설정을 고른 뒤 `시안 생성`을 누른다.
5. 최종 시안과 게시 프로필을 확인하고 `댓글 달기`를 누른다.
6. 크롬에서 댓글을 한 글자씩 입력하고 게시 여부를 확인한 뒤, 확인된 댓글을 삭제하고 결과를 이력에 남긴다.

뜨기 전 영상 찾기로 발견한 영상도 같은 화면에서 시안을 만들고 검토한 뒤 게시할 수 있다.

## 3. 영상 탐색과 자료 수집

### 영상 목록과 직접 입력

`영상 불러오기`는 `연애` 검색의 최근 영상 목록을 불러와 썸네일, 제목, 채널과 게시 날짜를 표시한다. 운영자는 목록에서 영상을 선택하거나 유튜브 영상 링크를 직접 입력한다. 동일 영상은 주소 형태가 달라도 영상 ID로 구분한다.

영상을 선택하면 제목과 설명, 한국어 수동 자막 또는 자동 자막, 해당 영상의 인기 댓글을 수집한다. 수집한 영상 자료와 장면은 저장해 같은 영상에서 시안을 다시 만들 때 재사용한다.

### 뜨기 전 영상 찾기

`연애` 검색에서 최근 영상의 조회수를 확인하고 다음 조건을 만족하는 영상을 표시한다.

| 조건 | 기준 |
| --- | --- |
| 조회수 | 두 번째 확인 시점의 조회수 1,000~5,000회 |
| 조회수 증가 | 실제 조회수를 최소 60초 간격으로 두 번 확인하고, 증가량을 시간당으로 환산했을 때 150회 이상 |
| 화면 표시 | 조회수, 측정 시각, 관측 간격, 증가량과 시간당 환산값 |
| 사용 범위 | 일반 영상과 같은 시안 생성, 검토 및 게시 |

관측 간격이 충분한 이전 조회수 기록이 있으면 이를 이용해 증가량을 계산한다. 발견한 영상에는 일반 영상과 같은 게시 조건, 계정 선택과 이력 관리가 적용된다.

## 4. 영상 장면과 시청자 반응 선별

### 장면 선별

한국어 자막을 약 60초 길이의 구간으로 묶고 30초 간격으로 살핀다. 연애 관계와 고민을 나타내는 표현, 제목 및 시청자 댓글과의 텍스트 유사도, 댓글에서 언급한 시각을 함께 반영해 장면을 정렬한다. 겹치는 장면은 줄이고 상위 최대 세 구간을 보여준다.

각 구간에는 시간, 대표 발언, 주변 자막과 관련 시청자 댓글을 연결한다. 댓글은 장면과의 텍스트 관련성을 기준으로 최대 세 개를 제시하고, 관련성이 낮은 인기 댓글에는 확인이 필요하다는 표시를 붙인다. 출연진 안내나 협찬 안내처럼 반응으로 보기 어려운 댓글은 제외한다.

자막이 없거나 수집에 실패하면 제목과 설명을 바탕으로 초안을 준비한다. 구체적인 장면이 없을 때는 운영자가 영상을 보고 발언이나 상황을 직접 추가하며, 확인된 장면을 선택해 새 시안을 생성한다.

### 참고 반응의 사용

참고 댓글은 영상의 사실 근거와 구분한다. 시청자의 말높임, 문장 호흡, 감정과 관점을 참고하되 댓글에만 적힌 사건을 영상 속 사실로 옮기거나 원문의 문장과 개인사를 복사하지 않는다. 영상에 나온 발언자와 행동, 사건의 순서를 유지하고, 의견이나 하려다 만 일을 실제로 벌어진 사실로 바꾸지 않는다. 화면에는 참고 댓글, 출처와 초안에 반영한 관점을 표시한다.

## 5. 댓글 작성 기준

### 기본 조건

| 항목 | 작성 기준 |
| --- | --- |
| 길이 | 공백과 문장부호를 포함해 40~120자 |
| 영상 맥락 | 선택한 영상의 구체적인 대사나 장면을 하나 이상 언급 |
| 영상별 차이 | 해당 영상의 상황과 시청자 반응에 맞춰 작성 |
| 운명원 언급 | 영상 반응 뒤의 끝부분에서 연애 사주에 대한 관심으로 연결 |
| 금지 내용 | 링크, 해시태그, 운명원을 직접 이용한 것처럼 지어낸 후기 |

운명원 언급은 마지막 두 문장 안에 두며, 그 뒤에 짧은 감상이 이어질 수 있다. 댓글 형식은 길이, 링크와 해시태그, 브랜드 위치와 직접 이용 후기 표현을 검사한다. 영상 장면과 댓글의 관계가 불명확하거나 진단상 검토가 필요한 경우에는 운영자가 장면과 최종 문장을 확인한다.

### 관점과 감정

| 화면 선택 | 댓글이 출발하는 관점 |
| --- | --- |
| 참고 댓글 관점 | 장면과 관련된 시청자 댓글의 입장과 감정을 참고 |
| 장면에 이입 | 등장인물의 대화와 선택을 보며 솔직하게 반응 |
| 경험에 비춰보기 | 장면과 어울리는 가상의 짧은 연애 경험을 떠올림 |
| 의견과 조언 | 장면 속 행동에 대한 생각이나 조언을 표현 |

공감하는 말뿐 아니라 답답함, 화남, 응원, 조언, 웃음과 망설임 등 여러 반응을 쓴다. 개인 경험은 가상의 시청자 관점으로 표현할 수 있으며, 모든 댓글에 경험을 넣지 않는다. 운명원을 직접 이용한 경험으로 꾸며 쓰지 않는다.

### 운명원 연결

운명원에 대한 말은 바로 앞의 장면과 감정에서 이어진다. 상황에 따라 `이래서 운명원에서 먼저 봐야 됨`, `이래서 다들 운명원 운명원 하는구나`처럼 직접적인 반응이나 `같은 이유로 또 부딪힐지 알 수 있을까요?`처럼 구체적인 질문, 기대나 짧은 혼잣말을 사용할 수 있다. 한 가지 어미나 `궁금하네요` 같은 마무리로 통일하지 않는다.

| 영상과 반응 | 이어갈 생각 |
| --- | --- |
| 소개팅의 대화에 설레거나 웃음이 난 장면 | 자신의 기대를 떠올리거나 가볍게 감탄하며 관심을 표현한다. |
| 헤어진 사람이 다시 만날지 망설이는 장면 | 엇갈린 마음에 공감하거나 같은 이유로 부딪힐지 구체적으로 걱정한다. |
| 관계에서 거절이나 다툼을 지켜본 장면 | 상대의 행동에 대한 답답함과 의견을 유지하며 앞으로의 관계를 생각한다. |
| 연애 심리에 관한 설명을 듣는 장면 | 자기 연애 경험을 떠올리고 인연에 대한 생각을 이어간다. |

다음은 장면과 관점에 따라 작성하는 댓글의 예시다. 첫 번째는 소개팅 장면에 이입한 반응이고, 두 번째는 연애 심리 설명을 자신의 경험에 비춰본 반응이다.

심각한 갈등을 가벼운 후회로 축소하지 않고, 어려운 선택이 사주만으로 쉽게 해결되거나 미래가 확정된다고 단정하지 않는다. 영상의 감정과 상황에 맞는 연결이 떠오르지 않으면 시안을 보류한다.

### 말투와 표기

참고 댓글의 말높임과 리듬을 장면에 맞게 사용한다. 자연스러운 경우에만 ㅋㅋ, ㅠㅠ, 감탄, 생략과 구어식 표기를 섞는다. 선택한 시안에는 가벼운 띄어쓰기나 맞춤법 변형을 허용할 수 있다.

현재 초안의 표기 변형은 미리보기에서 확인한 뒤 적용한다. 영상에서 인용한 발언과 운명원 관련 문장은 보호하고, 읽기 어려운 변형은 적용하지 않는다.

## 6. 시안 생성과 편집

### 생성

선택한 장면의 자막과 주변 맥락, 영상 제목, 관련 시청자 댓글, 선택한 관점과 말투를 사용해 고민 한 줄과 완성 댓글을 함께 생성한다. 영상 반응과 운명원 언급은 한 사람이 이어 쓴 하나의 댓글로 작성한다.

첫 영상 선택 시 기본 시안 하나를 자동으로 준비한다. 이후에는 장면, 관점, 말투, 구어식 표기와 참고 댓글을 조합한 뒤 `시안 생성`을 눌러 한 번에 반영한다. 설정을 바꾸는 동안은 새 시안을 자동으로 생성하지 않는다. 기존 시안은 화면에 남고, 현재 시안의 기준과 다음 시안의 설정을 구분해 보여준다.

형식에 맞지 않는 생성 결과는 조건을 전달해 한 번 다시 생성한다. 조건을 만족하지 못하거나 자연스러운 연결을 만들기 어려운 결과는 이유와 함께 보류한다.

### 편집과 시안 관리

초안은 화면에서 직접 수정할 수 있으며 편집 내용을 저장한다. 생성 중이나 Jev 검토 중에도 현재 글을 계속 볼 수 있고, 검토가 진행되는 동안 다른 설정으로 새 시안을 만들 수 있다. 새 시안은 기존 글과 별도로 저장하며, 운영자가 확인한 뒤 선택한다. `저장된 시안`에서 이전 시안과 적용된 교정안을 다시 열 수 있다.

Jev 결과와 교정안에는 검토한 시안과 문장을 연결한다. 검토 중 운영자가 수정한 글은 결과가 도착해도 덮어쓰지 않는다. 문장이 바뀌면 이전 진단으로 표시하고, 현재 댓글을 다시 진단할 수 있다.

## 7. Jev 진단과 교정

### 진단 항목

Jev는 선택한 장면, 참고 댓글, 시청자 관점, 초안과 비교 시안을 바탕으로 항목별 신호를 반환한다.

| 항목 | 살펴보는 내용 |
| --- | --- |
| 장면 오류 | 영상에 없는 행동, 발언자 또는 사건 순서를 사실처럼 썼는지 |
| 관점 이탈 | 선택한 시청자의 입장과 감정을 뒤집었는지 |
| 감정 축소 | 장면의 고민을 지나치게 가볍게 만들었는지 |
| 운명원 연결 | 앞의 장면과 생각에서 브랜드 언급으로 자연스럽게 이어지는지 |
| 광고투 | 개인의 반응보다 안내문이나 광고 문구처럼 읽히는지 |
| 반복 | 비교 시안과 생각의 전개 및 문장 구조가 겹치는지 |
| 말투 불일치 | 선택한 관점과 참고 말투에 맞지 않는 표현이 있는지 |
| 허구 이용 후기 | 운명원을 직접 이용한 경험을 사실처럼 썼는지 |

### 신호별 처리

1. 장면 오류 또는 허구 이용 후기 신호가 0.35 이상이면 다른 신호보다 우선해 사실 확인 대상으로 표시한다.
2. 그 밖의 항목에서 0.35 이상 0.75 미만의 신호는 운영자 검토 대상으로 표시한다.
3. 그 밖의 항목에서 0.75 이상의 신호가 있으면 해당 항목의 고정 교정 규칙을 고른다.
4. 프로그램은 선택된 규칙을 정해진 순서로 조합해 교정 지시문을 만든다. 원문을 기준으로 최대 한 번 교정하고, 형식에 맞는 교정안은 Jev로 다시 진단한다.
5. 교정안은 원문과 별도로 보여주며, 운영자가 선택하면 별도 시안으로 저장한다. 수정된 현재 댓글은 다시 진단한 뒤 해당 글의 교정안을 별도로 요청할 수 있다.

진단 신호와 교정 결과는 각 시안에 남는다. 검토 결과는 장면과 문장의 확인을 돕는 정보로 사용하며, 최종 선택은 운영자가 한다.

## 8. 계정, 게시와 이력

### 계정 선택

게시 계정은 유튜브1, 유튜브2, 유튜브3 중 직접 선택하거나 자동 배정할 수 있다. 자동 배정은 영상마다 유튜브1 → 유튜브2 → 유튜브3 순서로 돌아가며, 같은 영상의 재시도에는 기존 배정을 유지한다. 각 프로필은 `로그인 준비`로 열린 일반 크롬에서 운영자가 로그인하고 창을 닫아 사용한다.

### 게시와 삭제

게시 전에 시안의 길이와 금지 조건, 영상 장면, 현재 시안과 편집 상태, 영상별 게시 이력과 당일 사용량을 확인한다. 현재 시안의 Jev 검토가 진행 중이면 검토가 끝난 뒤 게시할 수 있다.

검사를 통과하면 선택한 프로필의 크롬을 열어 한국어 유튜브 댓글창에 최종 댓글을 **한 글자씩 입력**한다. 입력된 내용이 확인한 댓글과 일치하는지 검사하고 게시한 다음, 해당 계정과 댓글 내용이 일치하는 항목을 찾아 게시를 확인한다. 게시가 확인된 댓글은 같은 계정에서 삭제하고 삭제 결과를 기록한다.

### 운영 제한과 기록

- 한 영상에는 계정 하나의 댓글만 게시한다. 게시 여부를 확인해야 하는 영상도 중복 게시를 막는다.
- 하루 게시 상한은 기본 10건이며 한국 시간 날짜를 기준으로 모든 프로필의 사용량을 합산한다. 예약, 진행, 게시 확인 및 게시 여부 확인이 필요한 작업을 집계한다. 게시 후 삭제한 댓글도 한도와 이력에 포함한다.
- 화면에 크롬 열기, 입력, 게시, 내 댓글 확인과 삭제 결과를 표시한다. 실패하거나 게시 여부가 불명확하면 상태와 이유를 남기고 확인 화면을 기록한다.
- 게시 확인 후 삭제에 실패한 경우 이력에서 삭제를 다시 확인할 수 있다.

## 9. AI 연결과 기술 구성

### 생성 및 교정 API

| 연결 | 사용 설정 |
| --- | --- |
| 로컬 라우터 프록시 포트 | `10100` 포트를 통한 AI 연결과 선택한 모델. 기본 모델은 `google-vertex/gemini-4-hydrogen` |
| OpenAI API | 선택한 모델과 설정 화면에 입력한 API 키 또는 서버의 `OPENAI_API_KEY` |
| GCP API | Google Cloud 기본 인증, 프로젝트, 리전과 선택한 Vertex AI 모델 |

설정 화면에서 입력한 OpenAI 키는 실행 중인 서버 메모리에 유지한다. 생성과 교정은 선택한 연결을 사용하며, 오류가 나면 이유를 표시한다.

### Jev 진단 연결

| 연결 | 사용 설정 |
| --- | --- |
| 서드파티 라우터 | Experiential API를 통한 Jev 연결과 선택한 모델. 기본 모델은 `jev-latest:free` |
| 공식 Jev | 공식 Jev 연결, 선택한 모델과 서버의 `JEV_OFFICIAL_API_KEY` |

생성 API와 Jev는 서로 독립적으로 선택한다. 각 연결의 모델 설정을 따로 유지하며, 요청이 실패해도 선택하지 않은 다른 연결로 자동 전환하지 않는다.

### 주요 기술과 저장

| 역할 | 구성 |
| --- | --- |
| 대시보드와 로컬 API | HTML, CSS, JavaScript, Python, FastAPI |
| 영상, 자막, 인기 댓글 수집 | yt-dlp와 한국어 자막 처리 |
| 장면 및 댓글 선별 | 시간 구간, 연애 관련 어휘, 텍스트 유사도와 댓글 시각 |
| 댓글 작성과 교정 | 선택한 생성 API와 고정 생성/교정 지시문 |
| 진단 | 선택한 Jev 연결과 항목별 신호, 규칙 기반 교정 지시문 조합 |
| 크롬 입력과 확인 | Playwright와 계정별 Chrome 영구 프로필 |
| 게시 제한과 이력 | SQLite |

영상 자료, 시안별 편집 내용과 진단 결과, 연결 설정은 프로젝트의 로컬 저장소에 보관한다. 게시 이력과 조회수 관측 기록은 SQLite에 저장하고, 게시 확인과 실패 화면 및 실행 영상은 증거 폴더에 남긴다. API 인증 정보는 시안이나 이력에 기록하지 않는다.

댓글 작성과 교정의 세부 문구는 [댓글 생성 기준](../docs/prompts/natural-comment-generation.md)과 [댓글 교정 기준](../docs/prompts/natural-comment-correction.md)에 따른다.
