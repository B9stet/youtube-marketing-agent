# POC-05 게시 제한과 중복 방지

- 상태: 검증 완료 (2026-11-23)
- 우선순위: 필수
- 선행 조건: 게시할 영상 ID와 프로필, 로컬 기록 저장소
- 후속 과제: POC-07의 실제 게시

## 목적

게시 전 코드에서 영상별 중복과 일일 상한을 검사하고, 게시 여부가 불확실한 경우 중복 전송을 방지한다.

## 주요 요구사항

- 영상당 댓글은 한 건만 허용한다. 계정이나 프로필이 달라도 같은 영상 ID면 동일한 영상으로 처리한다.
- 같은 영상의 일반 주소, 짧은 주소, 추가 매개변수가 붙은 주소는 같은 영상 ID로 정규화한다.
- 하루 게시 상한의 기본값은 10건으로 두고 설정값으로 관리한다.
- 날짜 기준은 Asia/Seoul이며 00:00에 다음 날로 넘어간다.
- 전송 직전에 영상 중복 여부와 해당 날짜의 상한을 검사하고 실행 중인 요청도 예약해 중복 클릭을 막는다.
- 성공한 게시와 진행 중 또는 게시 여부가 불확실한 요청은 확인 전까지 한도에 포함한다.
- 게시 버튼을 누르기 전에 실패해 전송되지 않은 것이 명확한 경우에만 예약을 해제하고 재시도를 허용한다.
- 게시 버튼을 누른 뒤 결과가 불명확하면 확인 필요 상태로 남기고, 사용자가 결과를 확인하기 전까지 같은 영상을 재게시하지 않는다.
- 앱을 재시작해도 게시 이력과 확인 필요 상태가 유지된다.
- 날짜가 바뀌는 동안 요청이 대기했다면 전송 직전에 현재 날짜의 한도를 다시 검사한다.

## 주요 제약사항

- 같은 영상은 프로필이 달라도 한 건만 허용하고 하루 기본 상한은 10건이다.
- 중복 검사와 게시 예약을 하나의 일관된 처리로 묶어 중복 클릭이나 동시 요청을 막아야 한다.
- 전송 여부가 불확실한 요청은 확인 전까지 예약과 일일 한도를 유지한다.
- 한국 시간 날짜로 계산한다. Windows에서 Python 시간대 데이터를 사용할 때는 시간대 데이터의 설치 여부를 확인한다.
- 로컬 기록만으로는 이 프로그램 밖에서 과거에 게시한 댓글을 자동으로 모두 알 수 없으므로 실제 시험 전 게시 대상의 기존 기록을 확인한다.

## 기술 후보

| 후보 | 적용 방식과 고려할 점 |
| --- | --- |
| **SQLite + Python sqlite3** | 영상 ID와 예약 상태, 게시 시각을 로컬 DB에 저장한다. 트랜잭션과 적절한 고유 제약을 이용해 중복 검사와 예약을 함께 처리한다. |
| **JSON 파일 + filelock** | 파일을 잠그고 상태를 저장하는 대안이다. 충돌 방지뿐 아니라 비정상 종료 시 기록 복구와 안전한 파일 교체를 직접 설계해야 한다. |
| **Python zoneinfo + tzdata** | 한국 시간 날짜 계산에 사용한다. Windows에서는 시간대 데이터가 없을 수 있으므로 tzdata 사용 여부를 검증한다. |

권장 출발점은 **SQLite와 zoneinfo**다. 실패 후 재시도와 불확실한 예약을 구분하도록 상태 설계를 먼저 정한다.

참고: [Python sqlite3](https://docs.python.org/3/library/sqlite3.html), [Python zoneinfo 데이터](https://docs.python.org/3/library/zoneinfo.html), [filelock 설계](https://py-filelock.readthedocs.io/en/stable/concepts.html)

## 검증 사례

| 사례 | 기대 결과 |
| --- | --- |
| 이미 성공한 영상 ID를 다시 요청 | 프로필과 관계없이 차단 |
| 성공한 영상의 다른 URL 형식을 요청 | 같은 영상 ID로 인식해 차단 |
| 오늘 확정 및 예약 건수가 9건 | 다음 한 건 허용 |
| 오늘 확정 및 예약 건수가 10건 | 다음 건 차단 |
| 같은 영상의 게시 요청이 동시에 두 번 들어옴 | 한 건만 예약되고 다른 요청은 차단 |
| 게시 전 오류로 전송되지 않음 | 오류 기록 후 예약 해제 가능 |
| 게시 시도 후 확인 전에 연결 끊김 | 확인 필요 상태와 예약을 유지하고 재게시 차단 |
| 자정 전후로 날짜가 바뀜 | 한국 시간 기준 날짜별 한도를 전송 직전에 검사 |
| 프로그램 재시작 | 성공과 확인 필요 기록 및 제한 유지 |

위 사례는 가상 기록과 가상 게시 처리로 시험한다. 한도 검증을 위해 실제 댓글 10개를 게시하지 않는다.
