# POC-06 진행 상태와 실패 기록

- 상태: 검증 완료 (2026-11-23)
- 우선순위: 필수
- 선행 조건: 게시 작업과 로컬 기록 저장소
- 후속 과제: POC-07

## 목적

게시 작업의 현재 단계와 결과를 사용자가 알 수 있게 표시하고, 실패 원인과 화면을 남긴다.

## 주요 요구사항

- 최소한 준비, 프로필 여는 중, 입력 중, 게시 확인 중, 게시 확인 상태를 구분한다.
- 전송 전에 실패한 경우와 게시 여부가 불확실한 경우를 각각 실패와 확인 필요로 구분한다.
- 기록에 발생 시각, 영상 ID, 프로필 식별명, 최종 댓글, 단계, 성공 또는 실패 결과를 남긴다.
- 실패하면 이유와 당시 화면 캡처 경로를 남긴다.
- 브라우저가 열리지 않아 브라우저 화면을 캡처할 수 없으면 오류가 보이는 실행 화면 등 당시 확인 가능한 화면을 남긴다.
- 기록은 시간순으로 확인할 수 있고 프로그램을 다시 열어도 보존된다.
- 비밀번호, API 키, 쿠키는 기록이나 결과 화면에 포함하지 않는다.
- 게시 확인은 해당 계정 화면에서 작성한 댓글을 확인한 경우에만 표시한다.

## 주요 제약사항

- 실제 게시가 확인되기 전에는 완료로 표시하지 않는다. 전송 전 실패와 결과 확인이 필요한 상태도 분리한다.
- 영상 ID, 프로필, 댓글, 시각과 결과를 재시작 후에도 확인할 수 있어야 한다.
- 브라우저가 열리지 않았거나 이미 종료된 경우에는 브라우저 페이지 캡처를 사용할 수 없으므로 별도 화면 캡처 방법을 검증한다.
- API 키, 비밀번호와 쿠키는 로그나 캡처 결과에 남기지 않는다.

## 기술 후보

| 후보 | 적용 방식과 고려할 점 |
| --- | --- |
| **SQLite + Python logging** | 사용자에게 보여줄 작업 이력은 DB에, 진단 메시지는 로그에 기록한다. 상태와 기록 저장이 서로 어긋나지 않도록 설계한다. |
| **Playwright 페이지 캡처** | 브라우저 페이지가 살아 있는 오류 상황에서 해당 화면을 이미지로 남긴다. 브라우저가 없는 경우에는 별도 방법이 필요하다. |
| **Pillow ImageGrab 또는 Windows 화면 캡처** | 브라우저가 열리지 않은 상황에서 현재 실행 화면을 남기는 후보이다. 로컬 데스크톱에서 실제 캡처 가능 여부를 확인한다. |
| **콘솔 상태 출력 또는 간단한 로컬 화면** | PoC에서 상태 확인에 사용한다. 이후 대시보드에 연결할 수 있도록 상태 값을 화면 구성과 분리한다. |

권장 출발점은 **SQLite, Python logging, Playwright 캡처**이며, 브라우저 실행 전 실패는 데스크톱 캡처 방법을 별도로 시험한다.

참고: [Playwright 화면 캡처](https://playwright.dev/python/docs/screenshots), [Pillow ImageGrab](https://pillow.readthedocs.io/en/stable/reference/ImageGrab.html)

## 검증 절차

1. POC-01의 입력 시험을 실행하며 단계가 순서대로 표시되는지 확인한다.
2. 댓글 사용이 중지된 영상 또는 재현 가능한 오류로 실패를 한 번 발생시킨다.
3. 실패 이유와 화면 캡처 파일을 확인한다.
4. 게시 버튼을 누른 뒤 결과 확인이 끊긴 상황을 재현해 확인 필요 상태를 확인한다.
5. 프로그램을 다시 열어 사건 순서와 기록이 남아 있는지 확인한다.

## 통과 조건

- [x] 재현한 실패 한 건에서 이유와 화면 캡처를 확인할 수 있다.
- [x] 전송 전 실패와 전송 후 결과 불확실을 구분한다.
- [x] 영상, 프로필, 댓글, 시각, 결과가 시간순으로 남고 재시작 후에도 확인된다.
