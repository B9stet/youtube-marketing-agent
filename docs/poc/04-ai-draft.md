# POC-04 고민 정리와 댓글 초안 생성

- 상태: 검증 완료 (2026-11-23)
- 우선순위: 필수
- 선행 과제: POC-03
- 후속 과제: POC-01, POC-07

## 목적

영상 2개를 각각 분석해 영상 속 고민을 한 줄로 정리하고, 구체적인 근거를 반영한 서로 다른 댓글 초안을 생성한다.

## 입력과 결과

- 입력: 영상 ID와 제목, 설명, 확보된 자막 또는 스크립트, 인기 댓글, 각 자료의 출처.
- 결과: 고민 한 줄, 사용한 영상 근거, 댓글 초안, 글자 수, 검사 결과.
- 자막이 없거나 부족하면 어떤 자료를 사용했는지 함께 표시한다.

## 주요 요구사항

- AI API를 사용해 선택한 영상의 자료로 초안을 생성한다. 즉석 API 생성은 과제의 가점 항목이지만 PoC에서 함께 검증한다.
- 영상에서 다루는 연애 고민을 한 줄로 정리한다.
- 댓글에 영상 속 구체적인 장면이나 말 한 가지 이상을 반영한다.
- 영상 근거는 자막, 제목 또는 설명 등 영상 자체의 자료에서 확인한다. 시청자 댓글의 내용만으로 영상 속 발언을 단정하지 않는다.
- 댓글 전체는 공백과 문장부호를 포함해 40~120자로 한다. 화면과 서버는 사용자가 보는 글자 단위로 같은 수를 표시한다.
- 이번 PoC 초안은 영상 내용에 공감하는 문장만 생성하며 운명원과 사주를 언급하지 않는다.
- 운명원 문구가 필요한 최종 단계에는 사용자가 별도 문구를 댓글 맨 끝에 추가할 수 있다.
- 링크와 해시태그, 운명원을 직접 이용한 것처럼 꾸민 후기를 포함하지 않는다.
- 서로 다른 영상의 내용을 구분하며, 근거 없는 장면이나 발언을 만들지 않는다.
- 사용자가 초안을 보고 수정할 수 있다. 게시 직전에 수정된 최종 문장을 다시 검사한다.
- 자막 대체 자료에도 영상 속 구체적인 말이나 장면이 없다면 근거 부족으로 표시하고 사용자가 확인하기 전까지 게시하지 않는다.

## 주요 제약사항

- 댓글은 공백과 문장부호를 포함해 40~120자이며 영상 속 구체적인 말 또는 장면이 필요하다.
- 운명원을 추가하는 경우 마지막 문장에만 넣는다. 이번 실제 게시 시험은 공감 댓글만 사용한다.
- 링크, 해시태그, 운명원을 이용한 것처럼 꾸민 후기는 허용하지 않는다.
- JSON 형식이 맞더라도 영상 근거의 사실성이나 댓글의 자연스러움이 보장되는 것은 아니므로 사람이 대조한다.
- 모델의 응답 실패, 형식 오류와 근거 부족을 구분하고, 수정된 최종 댓글도 다시 검사한다.
- 글자 수는 사용자에게 보이는 글자 단위로 일관되게 계산한다. 한글 조합 문자와 이모지가 포함된 사례도 검증한다.
- AI API 사용에는 선택한 서비스의 키와 호출 비용 또는 사용 한도를 고려해야 한다.

## 기술 후보

| 후보 | 적용 방식과 고려할 점 |
| --- | --- |
| **OpenAI Responses API + Structured Outputs** | 고민, 영상 근거, 댓글을 정해진 JSON 구조로 받는 후보이다. 길이와 내용의 타당성은 애플리케이션에서 별도로 검사한다. |
| **Gemini API + Structured Outputs** | 같은 형태의 JSON 구조를 생성하는 대안이다. 사용 가능한 키와 모델, 실제 한국어 결과를 확인해 선택한다. |
| **Pydantic + Python 검사 코드** | API 응답의 필드와 타입을 확인하고, 브랜드 언급, 금지 표현과 길이 검사를 별도로 수행한다. 사용자에게 보이는 글자 수는 Unicode 글자 묶음 기준 계산을 검토한다. |

PoC에서는 사용자가 지정한 **10100번 로컬 AI 연결**을 통해 Gemini 모델을 사용했다. 생성 결과의 글자 수와 근거는 별도로 검사한다.

참고: [OpenAI Structured Outputs](https://platform.openai.com/docs/guides/structured-outputs), [Gemini Structured Outputs](https://aistudio.google.com/docs/structured-output), [Python regex 글자 묶음 지원](https://pypi.org/project/regex/)

## 검증 절차

1. 서로 다른 실제 영상 2개의 자료로 각각 고민과 댓글을 생성한다.
2. 각 공감 초안의 길이와 링크, 해시태그, 브랜드 문구의 부재를 검사한다.
3. 사람이 영상의 실제 근거와 초안을 대조하고 자연스러움과 허위 후기 여부를 판정한다.
4. 길이 제한 위반과 금지 표현을 포함한 문장을 각각 입력해 검사 실패를 확인한다.
5. 근거가 부족한 자료를 전달해 근거 부족 표시와 게시 제한을 확인한다.

## 통과 조건

- [x] 영상 2개에서 각각 고민 한 줄, 영상 근거, 댓글 초안이 생성된다.
- [x] 두 초안이 모두 40~120자이고 운명원이나 사주 문구 없이 영상에 공감한다.
- [x] 운명원 문구를 추가하면 마지막 문장에만 들어가며 전체 길이가 40~120자이다.
- [x] 각 초안이 해당 영상의 실제 말이나 장면에 맞고, 두 영상의 구체적인 내용이 서로 구분된다.
- [x] 두 초안 모두 링크, 해시태그, 꾸며낸 이용 후기가 없다고 검토자가 판정한다.
- [x] 수정 후에도 위반 문장은 게시 전에 차단된다.
- [x] 근거가 부족한 경우 그 상태를 표시하고 사용자 확인 전 게시하지 않는다.
